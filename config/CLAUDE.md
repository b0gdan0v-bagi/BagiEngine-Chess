# Chess config

The scene is `SceneConfig.xml` plus the node files of `config/nodes/` (the engine's "Node files", `engine/src/Modules/BECore/Scene/CLAUDE.md`); what the nodes do is in `src/Chess/Components/CLAUDE.md`, read it before changing the scene. An entry that changes a node edits only the file of that node. The settings files (`ChessSettings.xml`, the git-ignored `ChessSettings.local.xml`) are in `src/Chess/Engine/CLAUDE.md`, "The settings file".

| File | Holds |
|------|-------|
| `SceneConfig.xml` | the `scene` element (`ChessScene`), `viewVariants` (the default view 840 x 800, `Tall` 720 x 1204 up to the aspect 0.59, `Portrait` 720 x 960 and `Wide` 1120 x 800 from the aspect 1.4) with its comment, and the 45 `<node ref>` in the draw and input order (the order of the references decides it for one layer, so do not reorder): the thirteen UI nodes, then the 32 piece references with their group comments |
| `nodes/ChessBoard.xml`, `ChessBoardCoordinates.xml`, `ChessMaterial.xml`, `ChessMovePanel.xml`, `ChessHud.xml`, `ChessMenuPanel.xml`, `ChessOpponentPanel.xml`, `ChessMovesSection.xml`, `ChessGameSection.xml`, `ChessSoundPanel.xml`, `ChessPromotionPanel.xml`, `ChessResult.xml`, `ChessSound.xml` | the nodes `Board`, `BoardCoordinates`, `Material`, `MovePanel`, `Hud`, `MenuPanel`, `OpponentPanel`, `MovesSection`, `GameSection`, `SoundPanel`, `PromotionPanel`, `Result`, `Sound` (the node name has no prefix; the layer is the node's own) |
| `nodes/ChessPiece.xml` | the prefab of a piece; each of the 32 references overrides `name`, `spriteId`, `file` and `rank` (spelled out even when equal to the prefab's) |

A node file is named `Chess<Node>` because `ConfigManager` loads it as a config by its stem. A new file in `config/nodes/` goes into the list of `tests/check_web_package.cmake`, and the scene must reference it (`ChessSceneFilesTest` fails on a file nobody references). A test reads the scene through `tests/ShippedScene.h`, which expands the references, never with `load_file`: the nodes are not in the scene file.

**In the browser** the engine's web overlay (`engine/web/config/`: `ApplicationConfig.xml`, `LoggerConfig.xml`, `SDLWindowConfig.xml`) replaces a file of the same name **whole**; Chess has no web config of its own. Its `ApplicationConfig.xml` must stay the overlay's apart from `renderer` (`ChessWebConfigTest` fails otherwise): an attribute added here, such as a title or a `mode`, would be dropped in the browser. Do not give `config/` a file named like an overlay file. The files of `config/` and `assets/` that stay out of the web package (`*.md` such as this one, `*.local.xml`, `imgui.ini`, `.DS_Store`, `*.py`, `__pycache__`) are in `cmake/ChessWeb.cmake`; the files that go in are listed in `tests/check_web_package.cmake`; `BagiChessWebPackageCheck` fails when a new file appears there.
