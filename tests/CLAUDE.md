# Chess tests

Part of the Chess documentation, split out of the root `CLAUDE.md` (which holds the overview, the control API, the rules and the map of these files) so that a session loads it only when it works here. A section named in quotes may be in a sibling file: the scene and the UI in `src/Chess/Components/CLAUDE.md`, the opponent in `src/Chess/Engine/CLAUDE.md`, the rules in `src/Chess/Game/CLAUDE.md`, the tests in `tests/CLAUDE.md`.

`tests/`, executable `ChessTests` (the rules need no engine services; `ChessUiTest`, `EngineOpponentTest`, `OpponentControllerTest` and `OpponentChoiceTest` do). New rule code goes into `Game/` and gets a gtest case; see `engine/.claude/rules/tests-module.md`.

`plays: null` ends the programs and nothing moves afterwards. **The analysis scenario** runs on both clocks and needs nothing from the environment (the own engine): the default `analysis` is empty; on the manual clock only (no frame between the move and the request; on the real clock the own engine may answer first, and `ChessGameControlTest` checks it deterministically) a hint on the program's turn (`max`, right after the person's move) is `not_your_turn` with the version unchanged; `analysis` with a `fen` or an `opponent` and a wrong member are `invalid_params`; the evaluation is switched on (the version grows); on a mate in one loaded in a call of its own the evaluation becomes `{kind: mate, value: 1}` with text `#1` and no hint, and `lines` has two entries (the mating move with mate 1 first, another listed move second); the default `lines` is `[]`; a hint is asked for and becomes `a1a8`, which is in `list_actions`; a move drops the hint at once (and the evaluation, checked on the manual clock only: a fast search on the real clock may arrive before the read) and the evaluation follows (all waits limited by 30 s, a `step` per poll on the manual clock, no fixed sleep); the hint is taken back, and the game exits with code 0 after `quit` with the analyst running. Before the evaluation part the scenario checks **the ratings** (two people, the own engine): the defaults (`ratingsOn` false, `ratings` `[]`), `{"ratings": 1}` and `ratings` with a fen are `invalid_params`, the switch moves the version, `e2e4 e7e5 g1f3 b8c6` is played and `get_state` is polled (a time limit of 30 s, a `step` per poll on the manual clock, no fixed sleep) until `ratings` has four entries and none is `null`, every entry has a boolean `brilliant` that agrees with a `reason` of the four ids, and the reasons are the pinned `not_best, brilliant, not_best, brilliant`; a `reset` empties the list and keeps the switch, a frame passes (a replay before the rater has seen the empty game would keep the old ratings), and the same game gives the same ratings; the scenario ends with them switched off. On the headless run the hint is also seen on the board: the board band of a screenshot (`board_band`) with the hint differs from the one without it, equals it again once the hint is taken back, is the same when it is asked for a second time, and after a `reset` the opening is the band it was before any hint (the pictures are compared, how the hint looks is not checked). **The captured-material scenario** runs on both clocks and needs nothing from the environment: two people play `e2e4 d7d5 e4d5` by `perform_action`, and `get_state.material` is `{balance: 1, capturedByWhite: {pawn: 1, others 0}, capturedByBlack: all 0}` (the three keys and the five pieces are checked; the order of the keys on the wire is the alphabetical one of the JSON), the start position and a reset are all zero, and a position set with `set_state` has its material (two kings and a white rook: balance 5, every Black piece gone, every White piece but the rook); on the headless run the margin band of a screenshot (`margin_band`: the rows of the board, the columns left of it, so the HUD, which says other words in each picture, is left out) differs from the start after the capture, holds the cream of a row of the display (`232,210,170`) and is the start band again after a reset. The pictures are compared, not read: how the margin looks is not checked by it. **The opponent scenario** runs on both clocks against `tests/fake_uci_engine.py`: before the games start `main()` writes a `#!/bin/sh` wrapper (`exec <python> fake_uci_engine.py --moves e7e5,b8c6,g8f6`) into a temporary directory and puts it in `STOCKFISH` of the environment, which the game inherits from the script (`run_smoke` / `play` start it with the environment as it is). `$STOCKFISH` comes before `PATH` and the committed `config/ChessSettings.xml` has no path, so a Stockfish on the developer's machine is never used. If `config/ChessSettings.local.xml` exists its path would win over `$STOCKFISH`, so the scenario is left out with a printed notice (the smoke never edits a person's files); it is left out on Windows too. The scenario: `get_state` has `opponent.plays` null; `set_state {"opponent": {"plays": "black", "level": "max"}}` reads back (`max`, not `easy`: the low levels may answer with a random move of their own and the fake would not be asked, so only a level without the handicap brings the scripted reply); `perform_action e2e4`; wait until `moves == [e2e4, e7e5]` and `thinking` is false (real clock: poll `get_state`; manual clock: `step` between polls; a time limit of 30 s, no fixed sleep); `error` is null; `set_state {"opponent": {"plays": null}}`, then a move of each color by hand and the program stays out of it over ten frames. The game must exit with code 0 after `quit`, which also closes the child (`ChessGame::Stop()`). `tools/stockfish_bridge.py` plays the game against Stockfish and compares its legal moves with `list_actions` (the same cross-check against `GenerateLegal` runs inside `ChessTests` as `StockfishRefereeTest` when a Stockfish is installed; its tests are `tools/tests/`; the control client it uses is described in `engine/tools/control/CLAUDE.md`).

`tests/uci_smoke.py` is the other smoke, not a gtest: ctest runs it as `BagiChessUciSmoke` (`add_test` in `CMakeLists.txt`; exit code 77 when `BagiChessUci` is not built, so a `--target` list without it skips it). It starts the real `BagiChessUci` with pipes and talks UCI to it as a tournament tool does (Python 3, standard library only; a reader thread and a queue give every read a time limit, so a hung program fails instead of hanging ctest). One session: the handshake, `isready`, six plies where each `bestmove` (checked only for the form of a move) is fed back in the next `position` and `isready` proves that no `info string` refusal came, `Level easy` on a clock, a clock alone with `movestogo 1` that must answer within the clock, `go infinite` and `stop` after 300 ms (exactly one `bestmove`); then `go infinite` and `quit`, and `go infinite` and the end of the input, each ending with code 0; and every stdout line of all runs starts with a UCI keyword. The child is always killed.

`tests/match_smoke.py` is a smoke too: ctest runs it as `BagiChessMatchSmoke` (exit code 77 when `BagiChess`, `BagiChessUci` or the tool is missing, so a `--target` list without them skips it). It runs `tools/uci_match.py` as a child process with a time limit, with `BagiChessUci` as both engines (its `Depth` option stands in for the Elo option, so the numbers of the table are depths) and `BagiChess` as the referee, and needs no Stockfish: `--verify-openings` exits 0 with every line `ok`; a match of `depth=1` against the opponent at two steps, 2 games each, capped at 40 plies, exits 0 and writes a record with 2 pairs of 2 games (both colors, W + D + L is 2, every game has moves and a termination, the summary has an `elo`); a missing opponent exits 77. It checks the mechanics, not any strength. `tools/tests/test_match_*.py` (`BagiChessMatchToolTests`, `python -m unittest discover`) are the unit tests of the same tool: standard library `unittest`, also collected by pytest, no executable and no Stockfish (a scripted control server and `tools/tests/fake_uci_engine.py`); not gtest files, so they have no row in the table.

`tests/check_web_package.cmake` is a `cmake -P` script, not a gtest: ctest runs it as `BagiChessWebPackageCheck` (`add_test` in `CMakeLists.txt`, inside `ENGINE_BUILD_TESTS`; no Python, no executable, so it also runs in the web-like folder). It includes `cmake/ChessWeb.cmake` and checks (1) the exclude patterns on names alone (`config/CLAUDE.md`, any `*.md`, `*.local.xml`, `imgui.ini`, `.DS_Store`, `*.py` and `__pycache__` are excluded; `ChessSettings.xml`, `SceneConfig.xml`, `chess_test.png` and look-alikes such as `localxml.xml` are not), (2) that the files of the package, taken from `config/` and `assets/` of the checkout, are exactly `assets/chess_test.png`, `config/ApplicationConfig.xml`, `ChessSettings.xml`, `SceneConfig.xml` and `TextureLibrary.xml` (a new config or asset file fails it until the list in the script is changed on purpose), and (3) the same list in a scratch copy of the layout (`CHECK_DIR`, in the build folder) with a `CLAUDE.md`, a `ChessSettings.local.xml`, an `imgui.ini`, a `.DS_Store` and a `__pycache__` file around, which is what a developer's folder looks like. It checks the list and the patterns, not that emcc applies `--exclude-file` (that needs emsdk, slice 2).

`tests/fake_uci_engine.py` is the stand-in for Stockfish of the opponent tests (it is not `tools/tests/fake_uci_engine.py`, the pytest one of the bridge): Python 3, standard library only, written from the UCI protocol alone. It answers `uci`, `isready` and `go` with scripted moves (`--moves e2e4,e7e5,...`, then `bestmove (none)`) with scripted scores in its `info` line (`--scores cp:35,mate:3,mate:-2,...`, one per `go`, default `cp:10`), and can think for a while and obey `stop` (`--think-ms`, `--think-first-only`), hang, die (`--die-on-go`, `--die-once MARKER`), stay silent after `uci`, write lines in two pieces, flood or garble its output, surround the final `info` line with lines an analysis must not take (`--noisy-info`: an earlier depth, a lower bound, a `multipv 2` line, an `info string` with a score in it, an upper bound after the line; the final line is depth 2), send a final `info` line with no score (`--no-score`; with `--lines` and `MultiPV` above 1 no line of either depth carries one; the noise lines of `--noisy-info` keep theirs), play a search with several lines (`--lines e2e4:cp:30,d2d4:cp:20,g1f3:mate:3`, the same for every `go`: the first move is the `bestmove`; it remembers `setoption name MultiPV value N` and, with N above 1, prints depth 1 lines with a score that must not be taken and then depth 2 `info depth 2 multipv i score ... pv <move>` for i = 1..min(N, lines); with N = 1 the `info` line is the usual one with the first line's score; a move is not checked, so a test may script an illegal or repeated one), and refuse to leave on `quit`, end of input or `SIGTERM`; `--log FILE` records every line it receives. The flags are listed in the docstring of the script. The C++ side is `FakeEngineUtil.h` (`FakeEngineLaunch({flags})`, `TempDirectory` named after the suite and the test, `ReadFileLines`, `Lines`, `WaitForLogLine` to poll the log for a line, `SKIP_WITHOUT_FAKE_ENGINE()`); the root `CMakeLists.txt` gives `ChessTests` the interpreter as `CHESS_TEST_PYTHON` (the Python of the engine's CMake, the venv one when there is one), and a test that starts the fake skips itself when that is empty or on Windows. The process code is POSIX only and not in a `CHESS_NO_STOCKFISH` build (`UciProcess::Start` answers `Unsupported` wherever `CHESS_HAS_UCI_PROCESS` is 0, and `UciProcessTest` has the one test that checks it; `UciEngineTest` the two for a search and an analysis); a Windows implementation is a later step.

`ChessTestUtil.h` has the helpers (`Sq`, `Mv`, `PositionFromFen`, the perft FENs, `MirrorFen`: a FEN seen from the other side of the table, shared by `EvaluationTest` and `CapturedMaterialTest`, and checked by `EvaluationTest.TheMirrorHelperIsItsOwnInverse`). `SeededRandom.h` (header only) is the xorshift64 generator with a fixed seed that `OwnEngineTest`, `StockfishRefereeTest` and (through `GamePlay.h`) `StockfishGameTest` use (the same numbers on every platform, unlike `std::uniform_int_distribution`). `StockfishUtil.h` (header only) is how a test finds the real Stockfish: `StockfishPath()` (`FindStockfish({})`, nothing on Windows), `StockfishSettings(path)` for a `UciEngine`, `Describe(error)` (an `EngineError` as a sentence) and `SKIP_WITHOUT_STOCKFISH(path)`, which declares `path` or skips the test (the tests ship and install nothing of Stockfish). `GamePlay.h` (header only) is how a test plays a whole game through a `ChessGameModel`: `Player` (the next move for the side to move), `EnginePlayer(engine, limits)` (any `IChessEngine`, through `SearchRequest::FromModel` so the history goes with the request; an error fails the test), `RandomPlayer(random)` and `PlayGame(model, white, black, plyCap)` (every move must be accepted; `kDefaultPlyCap` = 120), used by `OwnEngineTest` and `StockfishGameTest`. `HudWords.h` (header only) has `AllHudWords()`: every word the HUD can show, taken from `StatusText` over a scratch game and from `OpponentText` (`turn`, `status`, `opponentError`: "" and every `EngineErrorKind` sentence), and `Rounds()` and `Publish(round)`, which sets those three `UIVars` to the word `round` of each list; the layout tests of the HUD and the panel (`ChessUiTest`, `ChessHudWebTest`) walk the rounds. The names of the segments of the panel (modes, colors, engines, levels) are not in it: they are elements of the scene that the tests walk and hold to the tables. `TestEngines.h` has the engine doubles that the tests of what uses an `IChessEngine` share (header only): `InstantEngine` (the first legal move), `MatingEngine` (a mate in one when there is one, else the first legal move: it ends a game with the program's move), `GatedEngine` (holds the answer until `Open()`, honors its token or ignores it, optionally a move chosen in advance), `FailingEngine`, all derived from `RecordingEngine` (`Calls()`, `Answered()`, `LastLimits()`), `CountingFactory` (an `EngineFactory` that logs its calls, the level ids and the engine ids (`Engines()`) and hands out engines in order, or fails), `AnalysingEngine` (`Analyse` answers a scripted line, or the first legal move with a given score, and for a request of two lines or more a second line, the first other legal move with the score of `SetSecondLine`; counts its calls, keeps `LastRequest()`; `Gate(honorsToken)` holds the answer until `Open()`; `FailWith(error)`) and `CountingAnalysisFactory` (an `AnalysisEngineFactory` that logs the engine ids it was asked for and hands out engines in order, or fails), and `WaitUntil` (polls with a time limit, no fixed sleep). `ChessUiTest` needs `ChessModule` linked whole (`WHOLE_ARCHIVE` in `CMakeLists.txt`), since the scene file names components that no test references. The rest of the scene glue (the result bar, the promotion sprite, how the highlights look) draws and is not covered by tests: check it by hand in `BagiChess`.

**Under `CHESS_NO_STOCKFISH`** (the web build's world, see `src/Chess/Engine/CLAUDE.md`, "The switch `CHESS_NO_STOCKFISH`"; on the desktop a build with `-DCHESS_NO_STOCKFISH=ON`, and the web-like folder below with it added). `StockfishUtil.h` and `FakeEngineUtil.h` use `CHESS_HAS_UCI_PROCESS` (not `_WIN32`) to say "no process code here", so every Stockfish and fake-engine test skips. Tests that assume Stockfish is what a game starts with use `kDefaultOpponentEngine` / `kStockfishAvailable` or `#if CHESS_NO_STOCKFISH`: `OpponentEnginesTest`, `OpponentChoiceTest` (`kDefaultEngineId`; the case that needs the failing Stockfish picks the name first), `OpponentControllerTest`, `ChessUiTest` (`StartFromTheStockfishName()`: picks the name `stockfish` for a case that walks from it, through a factory of the test) and `ChessGameControlTest` (its fixture picks the name through a factory that makes any double and keeps it; a new `OpponentController` over the default factory is what the `WithoutStockfish...` cases use). The cases that run only in that build: the default factory refuses `Stockfish` as `Unsupported` also while nobody plays and for a seat nobody plays (`OpponentControllerTest`, `OpponentChoiceTest`: a `ChoiceError` of the kind `Engine`, `PositionAnalystTest`: `MakeAnalysisEngine`, `ChessGameControlTest`: `engine_unavailable` on the wire for `engine` and for a seat object) and plays with the own engine; a factory of a test is still asked for `Stockfish`; `FindStockfish` finds nothing (`UciEngineTest`). The path-naming cases of the default factory (`LaunchFailed`) are in the other build only. **The panel:** `ChessBoardComponent` hides the segment `EngineStockfish` there, so `ChessUiTest` skips (`SKIP_WITHOUT_STOCKFISH_SEGMENT()`) the three cases that click it or walk the two engines (`TheEngineSegmentsPickBothEnginesAndTheDefaultIsStockfish`, `ClickingAnEngineSegmentOnTheScreen...`, `ARefusedStockfishPickOnThePanel...`), counts nine segments in `EverySegmentEmitsItsActionAndValue...` and does not click Stockfish in `TheEngineGroupTakesClicks...`; `TheStockfishSegmentIsHiddenExactlyWhenTheBuildHasNoStockfish...` says what is shown in each build (a hidden segment has an empty rect, `Own engine` fills the group and is selected), `ThePanelWithTheStockfishSegmentHiddenPassesTheMatrix...` holds the layout of the group of one segment (the size matrix, the narrowest window, a touch target) in every build by hiding the segment by hand, and `WithoutStockfishThePickOfTheNameOnTheActionIsRefused...` the refusal on the action (only in that build). The layout cases that read the canvas without a frame still lay out both segments, which is the worst case.

**Under `ENGINE_SINGLE_THREAD`** (`BE_SINGLE_THREAD=1`: the task system has an inline pool and no worker thread, a job runs on the calling thread, as in the browser). `ChessTestUtil.h` has the macro `SKIP_WITHOUT_WORKER_THREADS()`, which is `GTEST_SKIP() << "needs worker threads (BE_SINGLE_THREAD)"` in that build and nothing in the normal one (the same text as the engine's cases of `TaskSystemTest`). A test that begins with it needs a worker beside the test thread: a gate that a worker holds while the test thread opens it (`GatedEngine`, `AnalysingEngine::Gate`), a wait for `IsThinking()` while a search blocks, a search that never ends and must be cancelled from outside, or an engine that only ever stands in as "never answers" (a `GatedEngine` or a fake engine with `--think-ms` as the program's opponent, as the orientation, coordinate and watch cases of `ChessUiTest` and `ChessPieceAnimationTest` have it). Inline `Submit` runs the engine inside the first `Update`, so such a test would block the test thread until the double gives up (`kGateGiveUp` = 10 s in `TestEngines.h`, `kMustNotTimeOut` = 15 s in `EngineOpponentTest`) and then pass on the engine's `Timeout` without testing what it claims: a test like that is not allowed to pass that way, it begins with the macro. 91 tests have it (87 in the Windows web-like run; the four POSIX-only cases of `EngineOpponentTest` that use the fake engine with `--think-ms` or wait for `IsThinking()` skip there for the fake engine first), in `ChessGameControlTest`, `ChessUiTest`, `ChessPieceAnimationTest`, `EngineOpponentTest`, `MoveRaterTest`, `OpponentControllerTest`, `OpponentSeatsTest`, `PositionAnalystTest` and `OwnEngineTest` (`ShutdownDuringADeepSearch...`); a new test with a gate or a blocked search begins with it too. Every other test passes inline (an inline search finishes inside `Update`), and the web-like run has no test that takes more than a few seconds: a test near 10 s is one that is missing the macro. The web-like check on the desktop (no emsdk), from the repository root, on Windows through `python engine/CI/scripts/vs_env.py` (the interpreter is `python3` elsewhere):

```bash
python engine/CI/scripts/vs_env.py cmake --preset windows-clang-debug -B build/webcheck -DENGINE_WITH_VULKAN=OFF -DENGINE_SINGLE_THREAD=ON -DENGINE_STATIC_SDL=ON -DCHESS_NO_STOCKFISH=ON
python engine/CI/scripts/vs_env.py cmake --build build/webcheck --target ChessTests
ctest --test-dir build/webcheck -E "Smoke|ToolTests" -j8 --timeout 60
```

`BagiChess` does not start in that build (its `ApplicationConfig.xml` names `VulkanRendererBackend`, which a build without Vulkan does not register), so the smokes are left out, and each gtest is a ctest test of its own (`-R ChessTests` finds none). **Every build writes its executables and `lib/*.lib` into `build/ClangWindows/` whatever the build folder is, so the web-like build overwrites the desktop one:** after a web-like run delete `build/ClangWindows/lib/` and the executables, `.pdb` and `.dll` files there and rebuild the desktop preset before its `ctest`, and the other way round; remove `build/webcheck` when done.
