# Chess tests

Part of the Chess documentation, split out of the root `CLAUDE.md` so that a session loads it only when it works here. A section named in quotes may be in a sibling file: the scene and the UI in `src/Chess/Components/CLAUDE.md`, the opponent in `src/Chess/Engine/CLAUDE.md`, the rules in `src/Chess/Game/CLAUDE.md`.

`tests/`, executable `ChessTests` (the rules need no engine services; `ChessUiTest`, `EngineOpponentTest`, `OpponentControllerTest` and `OpponentChoiceTest` do). New rule code goes into `Game/` and gets a gtest case; see `engine/.claude/rules/tests-module.md`.

## The fake UCI engine

`tests/fake_uci_engine.py` is the stand-in for Stockfish of the opponent tests (not `tools/tests/fake_uci_engine.py`, the pytest one of the bridge): Python 3, standard library only, written from the UCI protocol alone. It answers `uci`, `isready` and `go` with scripted moves (`--moves`) and scores (`--scores`), and can think and obey `stop`, hang, die, stay silent, split or garble its lines, add noise an analysis must not take (`--noisy-info`), send no score (`--no-score`), play several lines (`--lines`, `MultiPV`) and refuse to leave on `quit`, end of input or `SIGTERM`; `--log FILE` records what it receives. The C++ side is `FakeEngineUtil.h` (`FakeEngineLaunch({flags})`, `TempDirectory`, `ReadFileLines`, `WaitForLogLine`, `SKIP_WITHOUT_FAKE_ENGINE()`); the root `CMakeLists.txt` gives `ChessTests` the interpreter as `CHESS_TEST_PYTHON` (empty: the test skips). The process code is absent where `CHESS_HAS_UCI_PROCESS` is 0 (a `CHESS_NO_STOCKFISH` build).

## The smokes and script tests

Not gtests, run under ctest; none needs a Stockfish unless said.

- **Scenarios** (`tests/scenarios/*.jsonl`, `be_add_game_scenario_tests`, ctest `BagiChessScenario.<file>`) are sessions that `engine/tools/control/bagi_play.py` plays on the manual clock with no Stockfish: `short_game`, `promotion`, `captured_material`, `opponent_panel` (the person's clicks only). A scenario cannot wait (no loop, no poll); what needs a reply of the program or the analyst, a picture, the real clock, a build-dependent answer or the fake Stockfish stays in the smoke (which also plays the start and the opening on the real clock). To add one: `engine/tools/control/CLAUDE.md`, "Scenario files".
- **`control_smoke.py`** (`BagiChessControlSmoke`, `be_add_game_control_tests`) starts `BagiChess --control --headless`, once on the real clock and once with `--manual-clock`, and drives the game through the control API: the start and the opening, screenshots that follow the model (a scene built by moves equals one set from the same FEN, last-move squares blanked). Its scenarios, each on both clocks: own engine, the opponent panel (`ui_click` by element name, `ui_tree`: what it shows in this build, the program's replies), watch of two programs, analysis, ratings, the pictures of the captured material, and the opponent scenario against `fake_uci_engine.py`. Pictures are compared, not read. Waits are polled (30 s limit, a `step` per poll on the manual clock), never a fixed sleep; a picture of the program's opening move is taken after `let_the_pieces_settle` (the move slides). The game must exit with code 0 after `quit`. The opponent scenario puts a `#!/bin/sh` wrapper around the fake into `STOCKFISH` (which comes before `PATH`) and plays at `max` (the low levels may not ask the fake); it is left out with a notice when `config/ChessSettings.local.xml` exists (the smoke never edits a person's files) and on Windows.
- **Without Stockfish** the smoke tells a `CHESS_NO_STOCKFISH` build by itself (the default `opponent.engine` is `own`, `default_engine(client)`): the opponent scenario ends with a notice, the panel scenario expects `EngineStockfish` hidden, and a base scenario checks that `stockfish` is `engine_unavailable` with the opponent and position unchanged (it ends at once in a build with Stockfish). It cannot run in the web-like folder (its renderer): configure a desktop build with only `-DCHESS_NO_STOCKFISH=ON` and run `python tests/control_smoke.py --exe build/windows-clang-debug/bin/BagiChess.exe`.
- **`uci_smoke.py`** (`BagiChessUciSmoke`; exit code 77, a skip, when `BagiChessUci` is not built) talks UCI to the real `BagiChessUci` over pipes as a tournament tool does (a reader thread and a queue, so a hung program fails): the handshake, six plies fed back, `Level`, a clock, `go infinite` and `stop`, `quit`, end of input; every stdout line starts with a UCI keyword. The child is always killed.
- **`match_smoke.py`** (`BagiChessMatchSmoke`; 77 when `BagiChess`, `BagiChessUci` or the tool is missing) runs `tools/uci_match.py` with `BagiChessUci` as both engines (`Depth` stands in for the Elo option) and `BagiChess` as the referee: `--verify-openings`, a small match, a missing opponent exits 77. `tools/tests/test_match_*.py` (`BagiChessMatchToolTests`, `unittest`, also pytest) are the unit tests of the same tool, with a scripted control server and `tools/tests/fake_uci_engine.py`; they have no row above.
- **`check_web_package.cmake`** (`BagiChessWebPackageCheck`, a `cmake -P` script in `ENGINE_BUILD_TESTS`; no Python, no executable: it also runs in the web-like folder) includes `cmake/ChessWeb.cmake` and checks the exclude patterns on names alone, that the files of `config/` and `assets/` that the package takes are exactly the list in the script (a new file fails it until the list is changed on purpose), also in a scratch copy of the layout with stray developer files around. It does not check that emcc applies `--exclude-file` (needs emsdk).
- `tools/stockfish_bridge.py` plays against Stockfish and compares its legal moves with `list_actions` (`StockfishRefereeTest` is the same check).

## Build variants

**Under `CHESS_NO_STOCKFISH`** (the web build's world, see `src/Chess/Engine/CLAUDE.md`, "The switch `CHESS_NO_STOCKFISH`"). `StockfishUtil.h` and `FakeEngineUtil.h` test `CHESS_HAS_UCI_PROCESS` (not `_WIN32`), so every Stockfish and fake-engine test skips. Tests that assume Stockfish is the default use `kDefaultOpponentEngine` / `kStockfishAvailable` or `#if CHESS_NO_STOCKFISH`. Cases that run only in that build check that the default factory refuses `Stockfish` as `Unsupported` and that `engine_unavailable` reaches the wire; the path-naming `LaunchFailed` cases run in the other build only. `ChessBoardComponent` hides the segment `EngineStockfish` there, so the `ChessUiTest` cases that click it skip with `SKIP_WITHOUT_STOCKFISH_SEGMENT()`; the one-segment group's layout is held in every build by hiding the segment by hand.

**Under `ENGINE_SINGLE_THREAD`** (`BE_SINGLE_THREAD=1`: an inline task pool, no worker thread, as in the browser). A test that needs a worker beside the test thread begins with `SKIP_WITHOUT_WORKER_THREADS()` (`ChessTestUtil.h`): a gate that a worker holds while the test thread opens it (`GatedEngine`, `AnalysingEngine::Gate`), a wait for `IsThinking()` while a search blocks, a search that never ends and must be cancelled from outside, an engine that stands in as "never answers". Inline `Submit` runs the engine inside the first `Update`, so such a test would block until the double gives up (`kGateGiveUp` in `TestEngines.h`, `kMustNotTimeOut` in `EngineOpponentTest`) and pass on the engine's `Timeout` without testing what it claims: that is not allowed, so a new test with a gate or a blocked search begins with the macro. A test that runs no `CoreManager` frame and waits for a search that may yield calls `PumpTaskFrame()` (a no-op in a threaded build). A test near 10 s in the web-like run misses the macro. Run that build through ctest, one test per process (`OpponentOverFramesTest` spends its frame budget in one frame). The check on the desktop (no emsdk), from the repository root, on Windows through `python engine/CI/scripts/vs_env.py` (`python3` elsewhere):

```bash
python engine/CI/scripts/vs_env.py cmake --preset windows-clang-debug -B build/webcheck -DENGINE_WITH_VULKAN=OFF -DENGINE_SINGLE_THREAD=ON -DENGINE_STATIC_SDL=ON -DCHESS_NO_STOCKFISH=ON
python engine/CI/scripts/vs_env.py cmake --build build/webcheck --target ChessTests
ctest --test-dir build/webcheck -E "Smoke|Scenario|ToolTests" -j8 --timeout 60
```

`BagiChess` does not start in that build (its `ApplicationConfig.xml` names `VulkanRendererBackend`, which a build without Vulkan does not register), so the smokes are left out, and each gtest is a ctest test of its own (`-R ChessTests` finds none). The build writes into `build/webcheck/bin` and `lib`; remove `build/webcheck` when done.
