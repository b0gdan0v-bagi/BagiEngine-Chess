# Chess tests

Part of the Chess documentation, split out of the root `CLAUDE.md` (which holds the overview, the control API, the rules and the map of these files) so that a session loads it only when it works here. A section named in quotes may be in a sibling file: the scene and the UI in `src/Chess/Components/CLAUDE.md`, the opponent in `src/Chess/Engine/CLAUDE.md`, the rules in `src/Chess/Game/CLAUDE.md`, the tests in `tests/CLAUDE.md`.

`tests/`, executable `ChessTests` (the rules need no engine services; `ChessUiTest`, `EngineOpponentTest`, `OpponentControllerTest` and `OpponentChoiceTest` do). New rule code goes into `Game/` and gets a gtest case; see `engine/.claude/rules/tests-module.md`.

The C++ side is `FakeEngineUtil.h` (`FakeEngineLaunch({flags})`, `TempDirectory` named after the suite and the test, `ReadFileLines`, `Lines`, `WaitForLogLine` to poll the log for a line, `SKIP_WITHOUT_FAKE_ENGINE()`); the root `CMakeLists.txt` gives `ChessTests` the interpreter as `CHESS_TEST_PYTHON` (the Python of the engine's CMake, the venv one when there is one), and a test that starts the fake skips itself when that is empty or on Windows. The process code is POSIX only (`UciProcess::Start` answers `Unsupported` on Windows, where `UciProcessTest` has the one test that checks it); a Windows implementation is a later step.

`ChessTestUtil.h` has the helpers (`Sq`, `Mv`, `PositionFromFen`, the perft FENs, `MirrorFen`: a FEN seen from the other side of the table, shared by `EvaluationTest` and `CapturedMaterialTest`, and checked by `EvaluationTest.TheMirrorHelperIsItsOwnInverse`). `SeededRandom.h` (header only) is the xorshift64 generator with a fixed seed that `OwnEngineTest`, `StockfishRefereeTest` and (through `GamePlay.h`) `StockfishGameTest` use (the same numbers on every platform, unlike `std::uniform_int_distribution`). `StockfishUtil.h` (header only) is how a test finds the real Stockfish: `StockfishPath()` (`FindStockfish({})`, nothing on Windows), `StockfishSettings(path)` for a `UciEngine`, `Describe(error)` (an `EngineError` as a sentence) and `SKIP_WITHOUT_STOCKFISH(path)`, which declares `path` or skips the test (the tests ship and install nothing of Stockfish). `GamePlay.h` (header only) is how a test plays a whole game through a `ChessGameModel`: `Player` (the next move for the side to move), `EnginePlayer(engine, limits)` (any `IChessEngine`, through `SearchRequest::FromModel` so the history goes with the request; an error fails the test), `RandomPlayer(random)` and `PlayGame(model, white, black, plyCap)` (every move must be accepted; `kDefaultPlyCap` = 120), used by `OwnEngineTest` and `StockfishGameTest`. `HudWords.h` (header only) has `AllHudWords()`: every word the HUD can show, taken from `StatusText` over a scratch game and from `OpponentText` (`turn`, `status`, `opponentError`: "" and every `EngineErrorKind` sentence), and `Rounds()` and `Publish(round)`, which sets those three `UIVars` to the word `round` of each list; the layout tests of the HUD and the panel (`ChessUiTest`, `ChessHudWebTest`) walk the rounds. The names of the segments of the panel (modes, colors, engines, levels) are not in it: they are elements of the scene that the tests walk and hold to the tables. `TestEngines.h` has the engine doubles that the tests of what uses an `IChessEngine` share (header only): `InstantEngine` (the first legal move), `MatingEngine` (a mate in one when there is one, else the first legal move: it ends a game with the program's move), `GatedEngine` (holds the answer until `Open()`, honors its token or ignores it, optionally a move chosen in advance), `FailingEngine`, all derived from `RecordingEngine` (`Calls()`, `Answered()`, `LastLimits()`), `CountingFactory` (an `EngineFactory` that logs its calls, the level ids and the engine ids (`Engines()`) and hands out engines in order, or fails), and `WaitUntil` (polls with a time limit, no fixed sleep). `ChessUiTest` needs `ChessModule` linked whole (`WHOLE_ARCHIVE` in `CMakeLists.txt`), since the scene file names components that no test references. The rest of the scene glue (the result bar, the promotion sprite, how the highlights look) draws and is not covered by tests: check it by hand in `BagiChess`.
