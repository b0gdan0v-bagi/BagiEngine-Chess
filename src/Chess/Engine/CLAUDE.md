# Chess opponent (src/Chess/Engine)

Part of the Chess documentation (overview, control API and rules are in the root `CLAUDE.md`). Siblings: `src/Chess/Components/CLAUDE.md` (scene and UI), `src/Chess/Game/CLAUDE.md` (rules), `tests/CLAUDE.md`. The wire of the opponent and the analysis is in the header comment of `src/Chess/ChessGameControl.h`.

## Files

`Engine/` is the opponent, a program that picks a move and analyses a position; it depends on `Game/`, never on `Components/`.

```
├── ChessEngine.*, Analysis.*, SearchRequest.*   IChessEngine (FindMove blocking; FindMoveAsync / AnalyseAsync as coroutines, request and token BY VALUE; the default bodies call the blocking call, so UciEngine and the doubles block, OwnEngine yields between slices, BlunderEngine forwards; Analyse defaults to Unsupported), the pure analysis (best line first, `Second()` null for one line), the request
├── UciProtocol.*, UciProcess.*, UciEngine.*   the UCI text (pure), a child process talked to in lines (a stub where CHESS_HAS_UCI_PROCESS is 0), the engine over them; FindStockfish(path)
├── EngineOpponent.*, OpponentController.*, OpponentChoice.*   the opponent of a game, its seats, the choice as the panel makes it
├── MoveRating.*, MoveRater.*, AnalysisEngineFactory.h, PositionAnalyst.*   the pure rule of a rating, the background rater, the background analysis
├── OpponentSettings.*, OpponentEngines.*, OpponentLevels.*, BlunderEngine.*, OpponentText.*   the Stockfish path, the engine pick (Stockfish, Own), the four strengths (easy, medium, hard, max), the handicap, the HUD words (the HUD words are pure, `Game/` must not know the engine, and the single source of the panel's words)
└── Evaluation.*, Search.*, TranspositionTable.*, OwnEngine.*   the engine of our own
```

## Engines and strengths

- **BlunderEngine** (the handicap): per request it decides whether this move is a blunder and then answers a random legal move without asking the wrapped engine. **The decision and the move are a pure function of the position, the percent and the number of moves of the request** (no clock, random device or state): reproducible everywhere (the manual-clock smoke relies on it), thread safe, a position that blunders at 15 % also blunders at 40 %, the same position blunders the same way every time. **`Analyse` is forwarded unchanged**: a hint or an evaluation is never spoilt. `WithHandicap` wraps in the default factory only; **a double given by `SetEngineFactory` is never wrapped**.
- **OpponentLevels:** per level Stockfish's `Skill Level` and move time, the own engine's depth, and `blunderPercent` (the share of moves a random legal move replaces, for both engines). **Why a handicap:** Stockfish at `Skill Level` 0 and `UCI_Elo` at its minimum are both about 1300-1400, far above a casual person, so `blunderPercent` is the one knob that reaches a beginner.
- **Search:** iterative deepening negamax with alpha-beta, quiescence, killer and history ordering and a transposition table (`tableEntries`, 0 = none; built per call only for depth 3 or more, so easy and medium allocate nothing). `excludedRootMoves` leaves moves out of the root list only (empty = the old search bit for bit). **The table and the draws:** a node whose subtree returned a repetition or 50-move draw stores nothing and a table result is used only where no 50-move draw can fall inside. **Deterministic for a fixed depth** (move, score, depth, node count), in one call or in any slices (`SearchSliceTest`); a search cut by a deadline or a token is not. **No recursion:** `Advance(maxNodes)` loops over heap frames, so a worker needs a few tens of KB at any depth. `SearchJob` owns copies of its inputs and pauses only between two nodes, so a pause changes no count or order; **a cancel between slices is seen at the start of the next `Advance`.**
- **OwnEngine:** `IChessEngine` over `Search`, in the process on every target, with the contract of `UciEngine` minus the process. `depth` is deterministic, `moveTimeMs` a deadline, both: the earlier. **`Analyse`:** line 1 is the one-line search (same move, score, depth and node count), line k a fresh `SearchJob` with the moves of lines 1..k-1 excluded at the root and its own table, so line 1 and the determinism are untouched. `BeginFindMove` / `BeginAnalyse` (`const`) validate and hand back a move-only **`OwnSearch`** (`Advance`, `IsDone`, `Result`). **`FindMove` and `Analyse` are "begin, `Advance(UINT64_MAX)`, read `Result()`"**: one implementation, so the one-call path cannot drift from a driven one.

## How it works

- **The opponent.** `FindMove` takes a `SearchRequest` (the start FEN and the moves), not a `Position`: UCI engines see repetitions only through the move list. Errors are values, `std::expected<Move, EngineError>`; a move that comes back is legal in the position the request leads to. **`UciProcess`:** on POSIX the child gets pipes for stdin and stdout, `/dev/null` for stderr and no other descriptor (the game's control socket stays out); a write to a dead child is `ProcessDied`, not `SIGPIPE`. On Windows the child runs in a job object with `KILL_ON_JOB_CLOSE`, so `Close()` ends what the child started too and a game that dies takes its engines with it.
- **The UCI engine** (`UciEngine`). **The path comes from the caller**; `FindStockfish(path)` only looks: the explicit path (it must be a file; no fallback when it is not), then `$STOCKFISH`, then `stockfish` on `PATH`. Stockfish is GPL-3.0: neither linked nor copied, no file of it enters this repository. The process starts on the first search and again after an error closed it. One search at a time (a mutex) and **`FindMove` and `Analyse` share it**, so a game that analyses while the program plays gives the analysis an engine object of its own (a second process), as `PositionAnalyst` does. A `Timeout`, `ProcessDied` or `ProtocolError` closes the process (not the missing score of `Analyse`: the engine answered), `NoMove` and `IllegalMove` keep it. **`Analyse`** is `FindMove` with a score (one private `RunSearch`, so the same commands, deadlines and errors): the last scored `info` of the main line, an exact one over a bound. **`MultiPV`** is sent only when N differs from what the running process has, so `FindMove` never runs with a leftover count. Line 1 is the `bestmove`; each other line is the first move of its `pv`, checked with `ParseUci`; duplicates and lines without a move are dropped, so the answer may have fewer lines than asked (not an error).
- **The switch `CHESS_NO_STOCKFISH`** (CMake option, forced ON when `ENGINE_TARGET_WEB`; the definition is `1` or `0` on `ChessModule`, so `#if` needs no `defined`). It is the web build's world (no child process in a browser); a desktop build can switch it on to check it. The process code is not compiled (Emscripten: unverified, needs emsdk), `FindStockfish` finds nothing and `kDefaultOpponentEngine` is `Own`. `MakeStockfishEngine` and `MakeAnalysisEngine(Stockfish, ..)` answer `UnavailableEngineError` (`Unsupported`). **The refusal is made in `ChooseSeats` for every seat choice, a seat nobody plays too**, so `set_state {"opponent": {"engine": "stockfish"}}` is refused even while nobody plays; **only while the controller uses its default factory**: a factory from `SetEngineFactory` is a test's own world and gets `Stockfish` as a name for its double, which is how the many tests that use the name still run in this build.
- **The opponent in a game** (`EngineOpponent(engine, side, limits)`). The main thread calls `Update(model)` once per frame and never waits. When it is the opponent's turn, the game is not over, no search runs and no error waits, `Update` copies the game and hands a task that `co_await`s `FindMoveAsync` to `TaskManager::Run` (Background pool); a later `Update` finds the answer and plays it with `TryMove`. **The model is read and written only in `Update`, on the main thread**; the task has a request copy and a state of its own in an `eastl::shared_ptr` passed by value, so nothing dangles whichever side ends first. **A stale answer is dropped:** when the model's `GetVersion()` has moved since the request (a reset, a `set_state`, a move of someone else) the search is cancelled and its answer thrown away, also when the engine ignores the token. A failed search or a move the model refuses is logged once (`LOG_ERROR`; with the controller, the analyst and the rater the only places in `Engine/` that log), kept in `GetLastError()`, and no search starts until `ClearError()`: a missing engine is one error, not a try per frame. **Shutdown:** destroy the opponent before `TaskManager::Shutdown()` (which joins the pool and would wait for a search nobody cancelled) and call no `Update()` after it.
- **The analysis in the game** (`PositionAnalyst`, no scene in it; owned by `ChessGame`, which calls `Shutdown()` in `Start()` (evaluation off, hint dropped) and in `Stop()` before `TaskManager::Shutdown()`; `ChessBoardComponent::OnUpdate` calls its `Update` after the opponent's; the control API reads and sets it, see `ChessGameControl.h`). `EngineOpponent`'s pattern: main thread only, one `Analyse` per version in a Background task. **One search serves all uses:** the evaluation (`SetEvaluation`, off by default: it costs a process and CPU) and the hint (`RequestHint(model)`); the best line is the hint's move and the evaluation's score, from the side to move's view. It asks for two lines; `GetLines(model)` is empty unless the evaluation is on or a hint was asked at this version and its answer has come. **The version rule:** the answer is kept for the model's `GetVersion()` at the request; a search whose version moved, or whose engine pick changed, is cancelled and its answer dropped, also from an engine that ignores its token; a hint belongs to its version (never asked again by itself), the evaluation follows the game. **Errors are per version:** a failed search is logged once and kept in `GetError()`; no search starts for that version; it goes with the next version, a change of the pick, or a new `RequestHint` (the retry). **The engine** is the one the person picked, made lazily by the `AnalysisEngineFactory` (`SetEngineFactory`; no handicap, the limits of the strongest level), **never the opponent's object** (so the opponent's search never waits for it), and **nothing falls back to the other engine.** **The hint rule** is the pure `HintRefusalFor(model, ProgramSides)`: `GameOver` on a finished game, `ProgramsTurn` when the program plays the side to move (either turn in a game of two programs), nothing for two people; `RequestHint` itself only refuses `GameOver`, callers ask `HintRefusalFor` first. `GetRevision()` grows with a switch, a hint asked or dropped, an answer that arrives and an error, never with a search that starts or ends. **The pick is told at once:** a caller that changes the pick between two frames and reads calls `SetPicked(engine)`, which cancels the other engine's search and drops its object, result and error, so no read shows the old engine's line.
- **The ratings of the moves** (`MoveRater`, no scene in it; **owned by `PositionAnalyst`**, which passes its factory on, calls `MoveRater::Update(model)` at the end of its own `Update`, forwards `Cancel()` and `Shutdown()` (which switches the ratings off and clears them) and adds the rater's revision to its own). The rule is `MoveRating.*` (brilliant = the engine's best move in the position before it, and a choice; the root `CLAUDE.md` has the wire). One `std::optional<MoveRating>` per played move in the order of `GetMoves()` (empty = not rated yet). **The engine is always the own engine at a fixed depth**: deterministic, so the same game gets the same ratings twice, with no process and no Stockfish; an object of its own, so its searches never delay the opponent. **Opt-in:** off at the start (it costs CPU); off cancels the running search and the ratings stay. **The history rule** (the history, not the model's version): a game that only grew keeps its ratings (unlike a hint); a game that is not an extension of the held one (another start FEN, a shorter or differing history: a reset, `SetPosition`) cancels the search, drops its answer (a generation counter, also from an engine that ignores its token), drops **all** ratings and the error, and starts again; **Errors:** an engine that cannot be made blocks the rater (one `LOG_ERROR`, nothing tried again); a failing search fails that one move and **the later moves are still tried**; both go with a new history, a switch off and on, and `Shutdown()`.
- **The sliced search.** The single-thread web build runs a task on the main thread between frames, so a blocking `OwnEngine::FindMove` / `Analyse` would freeze the page; `SearchJob` and `OwnSearch` are the same search as a machine that a coroutine drives `kSearchSliceNodes` at a time. **`moveTimeMs` is a wall-clock deadline counted from `Begin...`**, so time spent in other frames counts against it; the levels, the analyst and the rater use a depth, so nothing changes for them. `OwnEngine::FindMoveAsync` / `AnalyseAsync` (the additive virtual pair on `IChessEngine`) drive it and the three task bodies (`EngineOpponent`, `PositionAnalyst`, `MoveRater`) `co_await` them. The yield goes **before** the work (`TaskSystem/CLAUDE.md`, "The window"); on a threaded build `YieldIfNeeded()` never suspends. **Tests pump frames:** under `BE_SINGLE_THREAD` a task that yielded is resumed only by `TaskManager::Update`, so a test that runs no `CoreManager` frame and waits for a search calls `PumpTaskFrame()` (`ChessTestUtil.h`) in its loop.
- **The settings file.** A person's Stockfish comes from the attribute `stockfishPath` of the root element of two configs: `config/ChessSettings.xml` is committed with an empty value, `config/ChessSettings.local.xml` is git-ignored and holds their own. Two stems because `ConfigManager` keys a file by its stem. The local value wins when not empty; a missing file, attribute or value is "not set", never an error. The lookup order is the config line, then `$STOCKFISH`, then `stockfish` on `PATH`: an empty `stockfishPath` goes on, a non-empty one that names no file is not skipped (no fallback after a typo). `FromConfig(shared, local)` is pure and what the tests feed (`config/` is not mounted in gtest); `Load()` needs the engine services and `ChessGame::Start()` calls it.
- **The seat of the opponent** (`OpponentController(model, settings)`, no scene in it). It holds which side **the program** plays (`GetPlays()`; none = two people on one screen), the strength and the engine (both also while nobody plays) and the `EngineOpponent` behind them. A game starts with nobody: nothing is started until a side is picked. Every pick (`SetSide`, `SetLevel`, `SetEngine`, `Choose`, the `Cycle*` calls) destroys the old `EngineOpponent` first (its late answer is never played) and makes a new one from the factory:. While nobody plays, a pick only changes the choice and clears a standing pick error. **A pick that changes nothing does nothing** (a search in flight is kept, Stockfish is not restarted; also for `set_state`); with a pick error standing the same pick goes through the factory again, which is the retry. `Choose` is the whole choice in one pick. **The factory** (`SetEngineFactory`) is how every test avoids a real Stockfish; the default makes a `UciEngine` over `FindStockfish(stockfishPath)` for `Stockfish` and an `OwnEngine` for `Own` (it cannot fail), **each wrapped by `WithHandicap`**. **A pick of Stockfish succeeds whenever `FindStockfish` finds a file:** the program starts at its first search, so a file that is not an engine shows later as `LaunchFailed` of that search (`GetError()`); the program's side stays locked for the person until the version moves or another pick is made. **A pick that finds no engine is refused:** the engine is asked for FIRST and then **nothing changes** (side, level, engine, the running opponent and its search stay; `Choose` is all or nothing), the error is kept in `GetError()`, the revision grows once and one `LOG_WARNING` names the engine. **No fallback of any kind:** nothing picks the other engine for the person (the owner's decision). **The error rule:** an error belongs to the `GetVersion()` of the model it came from; when the version moves, the next `Update()` clears it (the opponent's too), and a new pick clears it. Until then nothing retries per frame; `PlaysFor(color)` stays true while an error stands. `GetRevision()` grows when the side, level, engine or error changes, never with a search or a move. **Two seats** (the control API's `plays: "both"` and `seats`; no panel yet): a `SeatChoice {engine, level}` per color and an `EngineOpponent` when the program plays it, each with an engine object of its own, never shared. `ChooseSeats(ProgramSides, white, black)` is the one pick and everything above wraps it: the factory is asked FIRST for every seat that plays and is new, changed or failed, and when any fails the whole pick is refused (nothing changes, running searches included); a seat with an unchanged color and choice keeps its opponent and search. **Reads:** `GetPlays()` is the one color the program plays and is NOTHING for nobody AND for both, so `BottomColor`, `OpponentChoice` and `ChessMaterialComponent` need no change and White stays at the bottom in a watch; `PlaysFor(color)` is true for any seat of that color; `GetLevel()` / `GetEngine()` are the seat that plays when exactly one plays, else White's. **Known gap:** `OpponentMode` has no `Watch`, so `OpponentChoice::Mode()` says `Two` while two programs play.
- **The choice of the person** (`OpponentChoice(controller)`). The controller and the control API speak of the color the PROGRAM plays; the panel speaks of the PERSON: a mode (Two players / Computer) and the person's color. This class turns between the views and **remembers the person's color while nobody plays**. `SetMode("computer")` plays the opposite of the remembered color, `SetMode("two")` plays nobody (the color stays). The ids are exact (lower case; anything else is a `ChoiceError` `BadId`, nothing changes, no engine is asked);. **`Color()` refreshes the remembered color from the controller:** while the program plays, the person's color is the opposite of `plays`, whoever set it, so a `set_state` is followed by the panel. **A known gap:** it refreshes only when `Color()` is read (once per frame), so two `set_state` calls with no frame between them leave White remembered.
- **The opponent in the game** (`ChessGame`, `ChessBoardComponent`). `ChessGame` owns the controller after the model and the choice after it, both before the control adapter; `GetActive()`, `GetActiveModel()`, `GetActiveOpponent()`, `GetActiveChoice()` reach them (null when Chess is not the active game). `Start()` resets the model and sets nobody, the default level and engine, so a game with no engine configured plays as two people. The board component calls the choice for the panel's actions (the `value` is an id). **The frame:** `IGame` has no per-frame hook, so `ChessBoardComponent` subscribes to `SceneEvents::SceneUpdateEvent` and calls `Update()` there, on the main thread; never in `OnDraw()`, which must not change the model. **The click guard:** `OnMouseDown` returns, after the "game over: a click starts the next game" branch, when `PlaysFor(model->GetTurn())` (either seat, so with two programs the board takes no click): `OnSquareClicked` does not know sides. It holds while a search error stands; the person's ways out are the Reset button, a pick in the panel and Two players. **Shutdown:** `ChessGame::Stop()` calls the controller's `Shutdown()`, and `GameManager::Shutdown()` runs before the task system shuts down, so no search holds the join of the pool. **The default is Stockfish and nothing falls back** (`Own` with `CHESS_NO_STOCKFISH`): without Stockfish the game says "Engine not found" until the person picks Own engine.
