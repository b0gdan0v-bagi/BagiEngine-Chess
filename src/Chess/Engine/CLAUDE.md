# Chess opponent (src/Chess/Engine)

Siblings: `src/Chess/Components/` (scene and UI), `src/Chess/Game/` (rules), `tests/`; the wire of the opponent and the analysis is the header comment of `src/Chess/ChessGameControl.h`.

## Files

`Engine/` is the opponent, a program that picks a move and analyses a position; it depends on `Game/`, never on `Components/`.

```
├── ChessEngine.*, Analysis.*, SearchRequest.*   IChessEngine (FindMove blocking; FindMoveAsync / AnalyseAsync as coroutines, request and token BY VALUE; the default bodies call the blocking call, so UciEngine and the doubles block, OwnEngine yields between slices, BlunderEngine forwards; Analyse defaults to Unsupported), the pure analysis (best line first, `Second()` null for one line), the request
├── UciProtocol.*, UciProcess.*, UciEngine.*   the UCI text (pure), a child process talked to in lines (a stub where CHESS_HAS_UCI_PROCESS is 0), the engine over them; FindStockfish(path)
├── EngineOpponent.*, OpponentController.*, OpponentChoice.*   the opponent of a game, its seats, the choice as the panel makes it
├── MoveRating.*, MoveRater.*, MoveReview.*, GameReviewer.*, AnalysisEngineFactory.h, PositionAnalyst.*, AnalysisText.*   the pure rules of a rating and of a move's loss, the background rater and reviewer, the background analysis, its words
├── DrawOffer.*, DrawOfferJudge.*   the pure rule of a draw offer (who may offer, when the program accepts) and the background judge that asks the own engine
├── OpponentSettings.*, OpponentEngines.*, OpponentLevels.*, BlunderEngine.*, OpponentText.*   the Stockfish path, the engine pick (Stockfish, Own), the four strengths, the handicap, the HUD words (pure, here because `Game/` must not know the engine; the single source of the panel's words)
└── Evaluation.*, Search.*, TranspositionTable.*, OwnEngine.*   the engine of our own
```

## Engines and strengths

- **BlunderEngine** (the handicap): per request it decides whether this move is a blunder and then answers a random legal move without asking the wrapped engine. **The decision and the move are a pure function of the position, the percent, the number of moves of the request and its seed** (`RollKey` in `VarietyRoll.*`; seed 0 = the choices of a game without one; no clock, random device or state): reproducible, thread safe, and a position that blunders at a percent also blunders at every higher one. **`Analyse` is forwarded unchanged**: a hint or an evaluation is never spoilt. `WithHandicap` wraps in the default factory only; **a double given by `SetEngineFactory` is never wrapped**.
- **OpponentLevels:** per level Stockfish's `Skill Level` and move time, the own engine's depth, and `blunderPercent` (the share of moves a random legal move replaces, for both engines) and `varietyMargin` (centipawns, the own engine only; the default factory passes it to `OwnEngine`; the weaker the level the wider, `max` 0).
- **Search:** iterative deepening negamax with alpha-beta, quiescence, killer and history ordering and a transposition table (`tableEntries`, 0 = none; built per call only for depth 3 or more, so easy and medium allocate nothing). `excludedRootMoves` leaves moves out of the root list only (empty = the old search bit for bit). **The table and the draws:** a node whose subtree returned a repetition or 50-move draw stores nothing and a table result is used only where no 50-move draw can fall inside. **Deterministic for a fixed depth** (move, score, depth, node count), in one call or in any slices (`SearchSliceTest`); a search cut by a deadline or a token is not. **No recursion:** `Advance(maxNodes)` loops over heap frames, so a worker needs a few tens of KB at any depth. `SearchJob` owns copies of its inputs and pauses only between two nodes, so a pause changes no count or order; **a cancel between slices is seen at the start of the next `Advance`.**
- **OwnEngine:** `IChessEngine` over `Search`, in the process on every target, with the contract of `UciEngine` minus the process. `depth` is deterministic, `moveTimeMs` a deadline, both: the earlier. **`Analyse`:** line 1 is the one-line search (same move, score, depth and node count), line k a fresh `SearchJob` with the moves of lines 1..k-1 excluded at the root and its own table, so line 1 and the determinism are untouched. `BeginFindMove` / `BeginAnalyse` (`const`) validate and hand back a move-only **`OwnSearch`**. **Variety:** with a margin and a request seed other than 0, `FindMove` (never `Analyse`) searches up to `kVarietyMaxLines` lines and answers, by `RollKey`, one within the margin of line 1; a mate ends the collecting (never varied); every line has the deadline of the whole call, and a line the clock stops is no candidate. Margin or seed 0 = the plain search.

## How it works

- **The opponent.** `FindMove` takes a `SearchRequest` (the start FEN and the moves), not a `Position`: UCI engines see repetitions only through the move list. Errors are values, `std::expected<Move, EngineError>`; a move that comes back is legal in the position the request leads to. **`UciProcess`:** on POSIX the child gets pipes for stdin and stdout, `/dev/null` for stderr and no other descriptor (the game's control socket stays out); a write to a dead child is `ProcessDied`, not `SIGPIPE`. On Windows the child runs in a job object with `KILL_ON_JOB_CLOSE`, so `Close()` ends what the child started too and a game that dies takes its engines with it.
- **The UCI engine** (`UciEngine`). **The path comes from the caller**; `FindStockfish(path)` only looks: the explicit path (it must be a file; no fallback when it is not), then `$STOCKFISH`, then `stockfish` on `PATH`. The process starts on the first search and again after an error closed it. One search at a time (a mutex) and **`FindMove` and `Analyse` share it**, so the analysis gets an engine object of its own (a second process), as `PositionAnalyst` does. A `Timeout`, `ProcessDied` or `ProtocolError` closes the process (not the missing score of `Analyse`: the engine answered), `NoMove` and `IllegalMove` keep it. **`Analyse`** is `FindMove` with a score (the same commands, deadlines and errors): the last scored `info` of the main line, an exact one over a bound.
- **The switch `CHESS_NO_STOCKFISH`** (CMake option, forced ON when `ENGINE_TARGET_WEB`; the definition is `1` or `0` on `ChessModule`, so `#if` needs no `defined`). It is the web build's world (no child process in a browser). The process code is not compiled, `FindStockfish` finds nothing and `kDefaultOpponentEngine` is `Own`. `MakeStockfishEngine` and `MakeAnalysisEngine(Stockfish, ..)` answer `UnavailableEngineError` (`Unsupported`). **The refusal is made in `ChooseSeats` for every seat choice, a seat nobody plays too**, so `set_state {"opponent": {"engine": "stockfish"}}` is refused even while nobody plays; **only while the controller uses its default factory**: a factory from `SetEngineFactory` is a test's own world and gets `Stockfish` as a name for its double. **The same holds on the desktop when no file is found** (`LaunchFailed`).
- **The opponent in a game** (`EngineOpponent(engine, side, limits)`). The main thread calls `Update(model)` once per frame and never waits. When it is the opponent's turn, the game is not over, no search runs and no error waits, `Update` copies the game and hands a task that `co_await`s `FindMoveAsync` to `TaskManager::Run` (Background pool); a later `Update` finds the answer and plays it with `TryMove`. **The model is read and written only in `Update`.** **A stale answer is dropped:** when the model's `GetVersion()` has moved since the request (a reset, a `set_state`, a move of someone else) the search is cancelled and its answer thrown away, also when the engine ignores the token. A failed search or a refused move is logged once and kept in `GetLastError()`; no search starts until `ClearError()`.
- **The analysis in the game** (`PositionAnalyst`, no scene in it; owned by `ChessGame`, which calls `Shutdown()` in `Start()` (evaluation off, hint dropped) and in `Stop()` before `TaskManager::Shutdown()`; `ChessBoardComponent::OnUpdate` calls its `Update` after the opponent's). `EngineOpponent`'s pattern: main thread only, one `Analyse` per version in a Background task. **One search serves all uses:** the evaluation (`SetEvaluation`, off by default: it costs a process and CPU) and the hint (`RequestHint(model)`); the best line is the hint's move and the evaluation's score, from the side to move's view. It asks for two lines; `GetLines(model)` is empty unless the evaluation is on or a hint was asked at this version and its answer has come. **The version rule** is in the class comment: a hint belongs to its version (never asked again by itself), the evaluation follows the game. **The engine** is the one the person picked (no handicap, the limits of the strongest level), **never the opponent's object**, and **nothing falls back to the other engine.** **The hint rule** is the pure `HintRefusalFor(model, ProgramSides)` (in a puzzle the program's seat is the side the solver does not play, `HintSeatsFor`); callers ask it before `RequestHint`.
- **The ratings of the moves** (`MoveRater`, no scene in it; **owned by `PositionAnalyst`**, which passes its factory on, calls `MoveRater::Update(model)` at the end of its own `Update`, forwards `Cancel()` and `Shutdown()` (which switches the ratings off and clears them) and adds the rater's revision to its own). The rule is `MoveRating.*`. One `Optional<MoveRating>` per played move in the order of `GetMoves()` (empty = not rated yet). **The engine is always the own engine at a fixed depth**: deterministic, so the same game gets the same ratings twice, with no process and no Stockfish; an object of its own, so its searches never delay the opponent. **Opt-in:** off at the start (it costs CPU); off cancels the running search and the ratings stay. **The history rule** (the history, not the model's version) is the longest common prefix L of the game and the held one (same start FEN, same first L moves): a game that only grew keeps its ratings (unlike a hint), and **a takeback keeps the ratings of the moves that remain**; what is past L (ratings, failures) and the error are dropped and rating goes on from ply L; a search for a ply `>= L` is cancelled and its answer dropped (a generation counter, also from an engine that ignores its token), one for a ply below L stays; another start FEN (a reset, `SetPosition`) is L = 0, everything goes. `GetRating(model, ply)` is one entry without building the list (what a display asks once per frame); both reads answer only below L, even before the next `Update()`; **Errors** (an engine that cannot be made, a failing search) are in the class comment.
- **The review of a finished game** (`GameReviewer`, the rule is `MoveReview.*`; **owned by `PositionAnalyst`**, which passes its factory on and forwards `Update`, `Cancel`, `Shutdown` and the revision, so `ChessGame` changed nothing). One own-engine search per position `0..n` at `kReviewDepth`, one line, oldest first, an engine of its own, never the analysis's; a last position with no legal move is not searched (`TerminalCentipawns`). **A review is of one exact game** (the start FEN and the moves at `Start()`): any other history drops it in every read at once (no prefix rule), and a late answer of an engine that ignores its token has nobody to reach. **The loss of a move** is `clamp(best) - clamp(-after)` at +-`kReviewClamp` centipawns, 0 for the engine's own best move and never negative; the scale (`best`, `good`, `inaccuracy`, `mistake`, `blunder`) is in `MoveReview.h`. A search that fails or an engine that cannot be made stops the review as `Failed` (one `LOG_ERROR`, `GetError()`, the positions that came stay, no retry; `Start()` restarts it); `Abandon()` drops everything.
- **The draw offer** (`DrawOfferJudge`, owned by `ChessGame`, the analyst's pattern and shutdown; its engine comes from `PositionAnalyst::MakeEngine`, so a test's factory reaches it). `PersonOffersDraw()` is every door's one body (two people agree at once); the board plays an `Accepted` verdict as `AgreeDraw()`. The rule is pure (`DrawOffer.*`). `Offer` runs one `AnalyseAsync` of the **own engine** at a fixed depth; `Update(model)` returns the verdict **once**, `GetState(model)` is the display's (`Declined` for the offer's version). Any change of the game drops the offer and its verdict. **An offer the program could not judge is declined** (`GetError()`); a version is never offered twice, so nothing retries by itself.
- **The sliced search.** The single-thread web build runs a task on the main thread between frames, so a blocking `OwnEngine::FindMove` / `Analyse` would freeze the page; `SearchJob` and `OwnSearch` are the same search as a machine that a coroutine drives `kSearchSliceNodes` at a time. **`moveTimeMs` is a wall-clock deadline counted from `Begin...`**, so time spent in other frames counts against it; the levels, the analyst and the rater use a depth, so nothing changes for them. `OwnEngine::FindMoveAsync` / `AnalyseAsync` (the additive virtual pair on `IChessEngine`) drive it and the task bodies (`EngineOpponent`, `PositionAnalyst`, `MoveRater`, `GameReviewer`) `co_await` them. The yield goes **before** the work (`TaskSystem/CLAUDE.md`, "The window"); on a threaded build `YieldIfNeeded()` never suspends.
- **Profiler zones.** `Chess search slice` is `OwnSearch::Advance` (blocking and coroutine alike); the tasks carry labels, `Chess move search`, `Chess analysis`, `Chess rating`, `Chess review`, `Chess draw offer` (the last four all run `AnalyseAsync`); `Chess opponent update`, `Chess analyst update` (the rater's and the reviewer's nested in it), `Chess rater update` and `Chess reviewer update` are one zone per main-thread frame. **No scope spans a `co_await`** (a zone ends on the stack that began it and a coroutine may resume on another thread): the label covers a task's first slice only; a slice resumed after `YieldIfNeeded()` is unlabeled. No zone inside the loop of `Search.cpp`.
- **The settings file.** A person's Stockfish comes from the attribute `stockfishPath` of the root element of two configs: `config/ChessSettings.xml` is committed with an empty value, `config/ChessSettings.local.xml` is git-ignored and holds their own. The local value wins when not empty; a missing file, attribute or value is "not set", never an error. An empty `stockfishPath` goes on to `$STOCKFISH` ("The UCI engine"). `FromConfig(shared, local)` is pure and what the tests feed (`config/` is not mounted in gtest); `ChessGame::Start()` calls `Load()`.
- **The seat of the opponent** (no scene in it). It holds which side **the program** plays (`GetPlays()`; none = two people on one screen), the strength and the engine (both also while nobody plays) and the `EngineOpponent` behind them. A game starts with nobody: nothing is started until a side is picked. Every pick destroys the old `EngineOpponent` first (its late answer is never played) and makes a new one from the factory. While nobody plays, a pick only changes the choice and clears a standing pick error (a pick of Stockfish while it is not offered excepted). **A pick that changes nothing does nothing** (a search in flight is kept, Stockfish is not restarted; also for `set_state`); with a pick error standing the same pick goes through the factory again, which is the retry. **The factory** (`SetEngineFactory`) is how every test avoids a real Stockfish; the default makes a `UciEngine` over `FindStockfish(stockfishPath)` for `Stockfish` and an `OwnEngine` for `Own` (it cannot fail), **each wrapped by `WithHandicap`**. **A pick of Stockfish succeeds whenever `FindStockfish` finds a file** (refused when it finds none, below): a file that is not an engine shows later as `LaunchFailed` of the first search (`GetError()`), and the program's side stays locked for the person until the version moves or another pick is made. **A pick that finds no engine is refused as a whole** (the engine is asked for FIRST; nothing changes, the running search included; one `LOG_WARNING`), and **nothing falls back** to the other engine (the owner's decision). **The error rule** is in the class comment. **Two seats** (the control API's `plays: "both"` and `seats`; no panel yet): a `SeatChoice {engine, level}` per color and an `EngineOpponent` when the program plays it, each with an engine object of its own, never shared. `ChooseSeats(ProgramSides, white, black)` is the one pick and everything above wraps it: the factory is asked FIRST for every seat that plays and is new, changed or failed, and when any fails the whole pick is refused (nothing changes, running searches included); a seat with an unchanged color and choice keeps its opponent and search. **Reads:** `GetPlays()` is the one color the program plays and is NOTHING for nobody AND for both, so `BottomColor`, `OpponentChoice` and `ChessMaterialComponent` need no change and White stays at the bottom in a watch; `PlaysFor(color)` is true for any seat of that color; `GetLevel()` / `GetEngine()` are the seat that plays when exactly one plays, else White's. `OpponentMode` has no `Watch`: `OpponentChoice::Mode()` says `Two` in a watch.
- **The choice of the person** (`OpponentChoice(controller)`). The controller and the control API speak of the color the PROGRAM plays; the panel speaks of the PERSON: a mode (Two players / Computer) and the person's color. This class turns between the views and **remembers the person's color while nobody plays**. `SetMode("computer")` plays the opposite of the remembered color, `SetMode("two")` plays nobody (the color stays). The ids are exact (lower case; anything else is a `ChoiceError` `BadId`, nothing changes, no engine is asked). **`Color()` refreshes the remembered color from the controller:** while the program plays, the person's color is the opposite of `plays`, whoever set it, so a `set_state` is followed by the panel. **Gap:** it refreshes only when `Color()` is read (once per frame), so two `set_state` calls with no frame between leave White remembered.
- **The opponent in the game** (`ChessGame`, `ChessBoardComponent`). `Start()` resets the model and sets nobody, the default level and `DefaultEngine()`, so a game with no engine configured plays as two people. **The frame:** `IGame` has no per-frame hook, so `ChessBoardComponent` subscribes to `SceneEvents::SceneUpdateEvent` and calls `Update()` there, on the main thread; never in `OnDraw()`, which must not change the model. **The click guard:** `OnMouseDown` returns, after the "game over: a click starts the next game" branch, when `PlaysFor(model->GetTurn())`: (either seat, as `OnSquareClicked` knows no sides; with two programs the board takes no click; the other color's click is a premove, `Components/CLAUDE.md`). **The premove:** `Update()` plays `PlayPremove()` after the seats' `Update` while the side to move is not the program's; a changed pick and `Shutdown()` drop the queue. It holds while a search error stands; the person's ways out are the Reset button, a pick in the panel and Two players. **Shutdown:** `ChessGame::Stop()` calls the controller's `Shutdown()`, and `GameManager::Shutdown()` runs before the task system shuts down, so no search holds the join of the pool. **Stockfish is offered** (`OffersStockfish()`) when the build can run it and a file is found (always with a test's factory); `DefaultEngine()` is Stockfish while offered, else Own, and a game starts with it. The answer is **cached** (`FindStockfish` walks `PATH`); `RefreshStockfish()` looks again at `SetSettings()` (every `Start()`; `ChessSettings.local.xml` is read there only), when the panel's opponent section opens and at every pick naming Stockfish (a fresh look). A Stockfish found later only becomes pickable; one that disappears after it was picked stays picked and its search fails with `LaunchFailed`, only its segment is hidden. The analysis follows `GetEngine()`.
