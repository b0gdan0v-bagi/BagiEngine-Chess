# Save: the game, the opponent choice, the audio levels and the look between runs

`ChessSaveState` (the file's content, `Capture`, `Validate`, `Apply`), `SaveSettings` (the switch and the folder policy), `ChessGraphicsState` (the look's file: `Capture`, `Validate`, `Apply`), `ChessSaveKeeper` (owned by `ChessGame`; also keeps the levels and the look). The storage is the engine's `SaveGameService` (`engine/src/Modules/BECore/Save/CLAUDE.md`; read "What a consumer does with a refused save"). The headers carry the contracts; this file the decisions around them.

## What is saved

Slot `game`, schema `{"Chess", 1, 1}`: the start FEN, the moves (UCI, one space-separated string), which colors the program plays, the engine and level id of each seat (the control API's ids, from the existing id tables) and the person's color. **Not saved:** selection, a pending promotion, the analysis switches, hints, ratings (they start off, as the root `CLAUDE.md` says), the takeback stack. A **finished** game is not restored (a new game starts); the opponent choice still is. A resignation or an agreed draw leaves only legal moves, so the file's `ended` (`""`, `"resigned"`, `"draw_agreed"`) makes it finished; who resigned is not kept. A new field needs no version (a file without it keeps the default); raise the version when a meaning changes, then an older program refuses the file as `VersionTooNew` and leaves it alone.

Slot `audio`, the engine's schema (`AudioPreferences`, `engine/src/Modules/BECore/Audio/CLAUDE.md`, "The player's levels"), in the same folder: the four levels the engine holds (master, `Sfx`, `Music`, `Ui`: volume and mute). The game's menu changes only the master; the rest stay the config's until a row exists.

Slot `graphics`, schema `{"ChessGraphics", 1, 1}`: one string, the preset id (`PresetId()`: `classic`, `beer`; `src/Chess/Graphics/CLAUDE.md`). A slot of its own, not a field of `game`, because that one is not written while a puzzle is on and a finished game is not restored, and the look must survive both. A file that is not there is Classic, the default.

## The gate (`ResolveSaveDirectory`)

A run reads and writes only when `config/ChessSettings.xml` (or `ChessSettings.local.xml`, which wins) says `rememberGame="true"` (the committed file does) **and** the run is not a control or headless one. `--control`, `--control-port=`, `--headless` and `--manual-clock` switch it off, so a control run neither reads nor overwrites a person's game or levels (one gate, one folder, one `SaveGameService` for both slots, so `--save-dir` and `--no-save` act on both); the flags are the contract because `Start()` runs before the control server and cannot read its resolved settings. `--no-save` switches it off everywhere; `--save-dir=<path>` is the explicit ask and turns it on in any run (this is how the smoke and the gtests exercise it, always with a temporary folder). `config/` is not mounted in `ChessTests`, so a gtest with no flag is clean. The folder: `--save-dir`, else `PersistentSaveDirectory()` (the browser), else `saves` under `SDL_GetPrefPath("BagiEngine", "BagiChess")` (on Windows `%APPDATA%\BagiEngine\BagiChess\saves`). A folder that cannot be made is one warning, persistence off, the game runs.

## When it reads and writes

- **Read:** once, at the end of `ChessGame::Start()`, into the fresh model and choice, with no dialog. **Write:** `ChessGame::UpdateKeeper()` (from `ChessBoardComponent::OnUpdate`, never a draw) when the key (model version, controller revision, person's color: no allocation) moved, at most once per `kSaveDebounceSeconds` of game time; and `Stop()` flushes first, before the opponent is shut down. **While a puzzle is on** (`ChessGame::IsPuzzleOn()`, passed to `Update` / `Flush` by the game, never kept) the game is not written, so a restart brings back the game from before it; the levels are still written, and the key is not marked as written, so the first frame after the puzzle saves the game it became. The browser tab that closes does not reach `Stop()`, which is why the debounced write exists.
- `Stop()` sets a flag: frames that still run after it write nothing, so the `Shutdown()` of the controller (two people) never becomes the saved choice. `Start()` clears it.
- What `Start()` restored is taken as already written, so a start writes nothing until the game changes; the levels likewise (the manager's `GetLevelsRevision()` after the load).
- **The levels and the look** are read after the game in `Start()` and written by `Update()` when `GetLevelsRevision()` / the `GraphicsChoice`'s `GetRevision()` moved, each with a debounce and a retry state of its own (`kSaveDebounceSeconds` after its last write; no write delays another), and by `Flush()`. Both go on while a puzzle is on. The keeper keeps the `GraphicsChoice` it was given in `Start()`; `ChessGame::Start()` sets Classic before the keeper restores the pick, and a reset leaves the look alone.

## A refused save

Everything is checked on scratch objects first (FEN with `Position::FromFen`, each move with `MoveGenerator::ParseUci` on a scratch position, each id and level against its table); only then it is applied, so a refusal changes nothing. One warning with the slot and the reason, never the contents; the same for the `audio` slot (the engine reads it into a temporary, so a refused file leaves the manager at the config's levels) and the `graphics` slot (the look stays Classic; an id no preset has is refused as `Corrupt` that names the field). **The file is left alone** (not deleted, not rewritten) until the game's own next change writes a good one. `NotFound` is silent (the first run); another game or a newer version is a refusal, never a crash. A pick the controller refuses at restore (Stockfish saved for a seat the program plays, none found now) is not a failure of the restore: the position comes back, the opponent stays two people, `opponent.error` says "Engine not found", nothing falls back to the other engine, and the next write saves what the game really has. A saved Stockfish of a seat the program does not play is only a memory: while none is offered `Apply` takes `DefaultEngine()` (Own) for that seat, so a start never shows "Engine not found" with nobody playing.

## Testing

`ChessSaveStateTest` and `ChessGraphicsStateTest` (round trips through a real `SaveGameService`, the damage list), `ChessSaveKeeperTest` (settings, policy, debounce with `CoreManager::GetTime().Advance`, never a sleep), `ChessSaveGameTest` (the real `GameManager` and scene, `--save-dir` set in the test), and the restart scenarios of `tests/control_smoke.py` (a real quit and start on one folder). A test that names a folder always uses a temporary one, never the person's.
