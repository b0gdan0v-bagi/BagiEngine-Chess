# The engine submodule and the todo folder

This repository is a game (Chess) that carries the BagiEngine as the git submodule `engine/`. The skills `todo-loop`, `todo-merge`, `todo-add`, `todo-sync` and the agents `todo-*` work the entries of `todo/` and `engine/todo/` (format: `todo/README.md`).

- **Style and contract:** the code style, DO and DON'T, the architecture and the `be_*` CMake functions are the engine's: read `engine/CLAUDE.md` and the nested `CLAUDE.md` files under `engine/src/` when a file there is read. The game's own `CLAUDE.md` (the root of this repository) comes first for anything about Chess; `README.md` has the build commands.
- **Tools come from the engine:** `engine/tools/todo_sync/todo_sync.py` run with `engine/.venv/bin/python` (`CI/setup_venv.*` of this repository creates the venv: it fetches `engine/` when missing, runs the engine's own script and installs the game's `requirements.txt` if there is one), from the root of this repository. There is no copy of the tool here.
- **The engine is developed from here.** The game is the proving ground of the engine, so engine work is done in this checkout, in the `engine/` submodule: an entry of `engine/todo/` is worked by `todo-loop` in a branch `todo/<id>` of the engine repository (cut from `games/chess`), and the work is tried live by building `BagiChess` with the engine on that branch. The vendored code (`engine/src/Modules/EABase/`, `EnTT/`, `fmt/`, ...) and `engine/external/` stay untouched. The areas (game and engine: todo folder, repository, base branch, tracker project) are in `.claude/rules/todo-project.md`.
- **The pointer of `engine/`.** The loop never moves it. `todo-merge` does, after the merge of an engine branch into `games/chess` and the owner's yes, as a commit of its own (`Update engine: <title>`); a pointer changed by hand is the owner's commit. While an engine branch is checked out, `git status` of this repository shows `engine` as modified; that is expected.
- **Skills and agents are one copy.** `.claude/skills/todo-{loop,merge,add,sync}` and `.claude/agents/todo-*.md` are symlinks into `engine/.claude/` (they need the submodule initialised). Change them there, in the engine repository; what differs between the repositories is in `.claude/rules/todo-project.md`. `build`, `clang-format` and `strip-pch-includes` are still copies.
- **The engine branch:** `engine/` follows the permanent branch `games/chess` of BagiEngine (`branch = games/chess` in `.gitmodules`), not `main`. It is the base branch of engine work: branches `todo/<id>` are cut from it and merged back into it. The owner merges `main` into it when the game should get newer engine work. `git submodule update --remote engine` brings the tip, and the new pointer is committed on its own.
- **Trackers:** two Vikunja projects, one per area: `BagiEngine-Chess` for `todo/` and `BagiEngine` for `engine/todo/`. The `.env` of this repository (git-ignored) holds the URL and token; **every `pull` and `push` passes `--project` explicitly** (the tool's default is `BagiEngine`, and `push` closes the tasks of entries that are not in the given `--todo` folder, so a run with the wrong pair of `--todo` and `--project` would close the other area's tasks).
- **Plans** live in the local store `~/.claude/plans/` and are not committed (`todo/README.md`).
