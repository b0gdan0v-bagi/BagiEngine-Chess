# Chess: the computer opponent works in the window; no analysis, resign or takeback, and no engine of our own

**Where:** `src/Chess/Game/ChessGameModel.h` (`OnSquareClicked` is the path of a person, `TryMove` the path of anything else; the model has no notion of a side played by a program), `src/Chess/Components/` (the board, the pieces and the result bar), `src/Chess/Game/Position.h` (`DoMove` / `UndoMove` exist), `src/Chess/Engine/` (the opponent core, see item 2: `ChessGame` owns the controller of it), `tools/stockfish_bridge.py` (the only way a whole game is played against Stockfish today), `engine/src/Modules/TaskSystem/` (a search runs off the main thread).

**What is missing** (found by reading the code and searching `src` and `tools`, not by playing):

1. A person can play the computer in the window (this branch): the Opponent button opens a panel where the mode (Two players or Computer), the color the person plays, the engine (Stockfish or Own engine) and the level are picked, and the program answers, with a Stockfish the person installed (the path in `config/ChessSettings.local.xml`, `$STOCKFISH` or `stockfish` on `PATH`; README "Playing against the computer") or with the engine of the game itself, which needs nothing. Nobody has played a whole game against a real Stockfish in the window yet (that is the owner's check). `tools/stockfish_bridge.py` stays the independent referee: it plays a whole game against Stockfish through the control API and compares the legal moves with `list_actions`, which the game's own opponent cannot do for itself; it needs the control API switched on, Python and an installed Stockfish, and a person at the window on the real clock (not tried yet, see the control entry (engine entry `control-api-gaps`)).
2. **What exists** (this branch, `src/Chess/Engine/`, covered by `ChessTests`): the interface `IChessEngine::FindMove(SearchRequest, CancellationToken)` (the request is the start FEN, the moves and the limits; errors are `EngineError` values), a UCI client over a POSIX child process (`UciProcess`, `UciEngine`: handshake, timeouts, `stop`, a new process after an error; `FindStockfish` looks for a path, nothing is shipped), the asynchronous driver `EngineOpponent` (it plays one side of a `ChessGameModel`: `Update` on the main thread starts the search on the `TaskManager` Background pool and plays the answer with `TryMove`; stale answers are dropped by `GetVersion()`), `OpponentController` (the seat: the side, the strength, the engine factory, the error rule), which `ChessGame` owns and `ChessBoardComponent` updates every frame, with the clicks of the person ignored on the program's turn and the opponent destroyed in `Stop()`, the Opponent button of the HUD and the panel it opens, which pick the mode, the color, the engine and the strength (with "Computer is thinking" and the engine's error in the words of the HUD), and gtests against a fake UCI engine (`tests/fake_uci_engine.py`) that need no Stockfish, plus `UciEngineStockfishTest`, which skips itself without one. **An engine of our own exists** (this branch, `src/Chess/Engine/`, covered by `ChessTests`): `Evaluation.*` (material and piece-square tables), `Search.*` (iterative deepening alpha-beta with quiescence, a check extension and move ordering; deterministic for a fixed depth, checked against a plain minimax and with pinned numbers) and `OwnEngine`, an `IChessEngine` over them that honors the depth, the move time and the `CancellationToken`, in the game's own process on every target. Measured in a Debug build on macOS, the search runs at about 0.8 to 1.3 million nodes per second (Kiwipete at depth 4: about 90000 nodes in 0.1 s; depth 5 to 6 is about a second in a middlegame). **It is wired into the game (slice 4):** the person picks it in the Engine row of the opponent panel (or `opponent.engine` of the control API), its levels are a depth each (1 / 2 / 3 / 5 since 2026-11-05, first guesses to tune by hand; a fixed depth is deterministic, a cap of 10 s only protects the window). **The levels were retuned on 2026-11-05 after the owner played the window** ("Stockfish even on Easy is very strong": Stockfish at `Skill Level` 0 is still a 1300-1400 player and `UCI_Elo` has the same floor): Skill Level 0 / 0 / 5 / 20 and, for both engines, a handicap in `src/Chess/Engine/BlunderEngine.*` that replaces 40 % (Easy) and 15 % (Medium) of the program's moves by a random legal move, a pure function of the position; the ladder is a first guess to be checked by playing, not a measured strength, and a fifth "Beginner" level is not added (the width of the Level group; the owner's call), the default engine is Stockfish and nothing falls back from one to the other, and it is covered by gtests and by a smoke scenario on both clocks that needs no process. **What is still missing of it:** it has no transposition table or opening book, and its strength has not been measured against Stockfish (a match through `tools/stockfish_bridge.py`). **What is still missing:** no file picker for the engine path (the setting exists, `stockfishPath` in `config/ChessSettings.xml` and the git-ignored `ChessSettings.local.xml`, and `ChessGame` hands it to the opponent); no Windows process code (`UciProcess::Start` answers `Unsupported` there), and the web target and Android cannot start a process. Stockfish is GPL-3.0 and the repository has no license file, so what linking or shipping it would require is not settled; the game only starts a copy the user installed. An engine for the web target has to run in the game's own process.
3. There is no analysis of any kind: no evaluation, best move or lines, no move list on the screen, no takeback, no stepping through the game, no resign or draw offer, no clocks, no PGN. The model keeps `GetStartFen()` and `GetMoves()`, which are enough to rebuild any earlier position, and `Position::UndoMove()` exists, but no player action uses them. The engine can draw text now (`TextComponent`, `BECore/Text/CLAUDE.md`), but there is no in-game UI to lay out a move list, a number or an opening name (No in-game UI (engine entry `in-game-ui`)).
4. Some choices a person needs still have no place to live. The mode, the color, the engine and the strength of the opponent have one now (the Opponent button in the top margin of the board and the modal panel it opens, four choice groups on the engine's `UISegmented`; it replaced the Side, Engine and Level cycle buttons, which the owner found bad for the side: that was the follow-up entry `chess-hud-opponent-panel`, done with this slice) and a new game is the Reset button. The piece of a promotion has one now (done with slice 2): a click on a promotion target does not move, it leaves the promotion pending in the model and opens the modal `PromotionPanel` (Queen, Rook, Bishop, Knight, Cancel); the buttons are plain text, there is no Escape or click outside to cancel, and the panel has no HTML + CSS twin. The board flip is done (slice 4 of this entry, 2026-11-06): the board is drawn from Black's side while the program plays White (Computer with the person's color Black), read live from the opponent and only the screen geometry turns (the model, the control API and the pieces' sprites do not); two people keep White at the bottom and a color picked while two people play turns the board only when Computer is picked. Still without one: resign and takeback.

**Decided by the owner (2026-11-03), the opponent:**

1. An abstract engine interface in the game (`src/`) ("a move for this `Position` within this time or strength") that runs the search off the main thread through `TaskManager` and plays the answer with `TryMove` on the main thread, so the model and the scene stay as they are.
2. First implementation: Stockfish as a separate child process over UCI (the logic of `UciEngine` in `tools/stockfish_bridge.py` ported to C++), the path chosen by the user, nothing shipped. This keeps GPL-3.0 code out of the game and out of `engine/` (other games of the engine may be sold; GPL code must never enter `engine/`). It works on desktop only: the web target cannot start a process and Android only in ways an app should not rely on.
3. Later, behind the same interface: an engine of our own in `src/` (alpha-beta over the existing `MoveGenerator`), in the game's process on every target and deterministic for a fixed depth (the manual clock and the smoke tests need that). Linking Stockfish in is not planned.
   - 2026-11-04: first part done: the engine core (evaluation, search) and `OwnEngine`; wiring left.
   - 2026-11-04: wiring done: chosen in the window (the Engine button), default Stockfish, no fallback.
4. Confirmed by the owner (2026-11-03, after the first slice): Stockfish is never shipped or linked, because the repository has no license file; the user downloads and installs it. No Stockfish binary, source, network file or copied text goes into the repository.

A file picker comes later, when the in-game UI has one (engine entries `in-game-ui` and `ui-authoring`).
