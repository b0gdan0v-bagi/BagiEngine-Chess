# Chess: the computer opponent works in the window; no analysis, resign, takeback or promotion choice, and no engine of our own

**Where:** `src/Chess/Game/ChessGameModel.h` (`OnSquareClicked` is the path of a person, `TryMove` the path of anything else; the model has no notion of a side played by a program), `src/Chess/Components/` (the board, the pieces and the result bar), `src/Chess/Game/Position.h` (`DoMove` / `UndoMove` exist), `src/Chess/Engine/` (the opponent core, see item 2: `ChessGame` owns the controller of it), `tools/stockfish_bridge.py` (the only way a whole game is played against Stockfish today), `engine/src/Modules/TaskSystem/` (a search runs off the main thread).

**What is missing** (found by reading the code and searching `src` and `tools`, not by playing):

1. A person can play the computer in the window (this branch): the Side button picks "Two players", "You: White" or "You: Black", the Level button the strength, and the program answers, with a Stockfish the person installed (the path in `config/ChessSettings.local.xml`, `$STOCKFISH` or `stockfish` on `PATH`; README "Playing against the computer"). Nobody has played a whole game against a real Stockfish in the window yet (that is the owner's check). `tools/stockfish_bridge.py` stays the independent referee: it plays a whole game against Stockfish through the control API and compares the legal moves with `list_actions`, which the game's own opponent cannot do for itself; it needs the control API switched on, Python and an installed Stockfish, and a person at the window on the real clock (not tried yet, see the control entry (engine entry `control-api-gaps`)).
2. **What exists** (this branch, `src/Chess/Engine/`, covered by `ChessTests`): the interface `IChessEngine::FindMove(SearchRequest, CancellationToken)` (the request is the start FEN, the moves and the limits; errors are `EngineError` values), a UCI client over a POSIX child process (`UciProcess`, `UciEngine`: handshake, timeouts, `stop`, a new process after an error; `FindStockfish` looks for a path, nothing is shipped), the asynchronous driver `EngineOpponent` (it plays one side of a `ChessGameModel`: `Update` on the main thread starts the search on the `TaskManager` Background pool and plays the answer with `TryMove`; stale answers are dropped by `GetVersion()`), `OpponentController` (the seat: the side, the strength, the engine factory, the error rule), which `ChessGame` owns and `ChessBoardComponent` updates every frame, with the clicks of the person ignored on the program's turn and the opponent destroyed in `Stop()`, the Side and Level buttons of the HUD that pick the side and the strength (with "Computer is thinking" and the engine's error in the words of the HUD), and gtests against a fake UCI engine (`tests/fake_uci_engine.py`) that need no Stockfish, plus `UciEngineStockfishTest`, which skips itself without one. **What is still missing:** no file picker for the engine path (the setting exists, `stockfishPath` in `config/ChessSettings.xml` and the git-ignored `ChessSettings.local.xml`, and `ChessGame` hands it to the opponent); no Windows process code (`UciProcess::Start` answers `Unsupported` there), and the web target and Android cannot start a process; no engine of our own. Stockfish is GPL-3.0 and the repository has no license file, so what linking or shipping it would require is not settled; the game only starts a copy the user installed. An engine for the web target has to run in the game's own process.
3. There is no analysis of any kind: no evaluation, best move or lines, no move list on the screen, no takeback, no stepping through the game, no resign or draw offer, no clocks, no PGN. The model keeps `GetStartFen()` and `GetMoves()`, which are enough to rebuild any earlier position, and `Position::UndoMove()` exists, but no player action uses them. The engine can draw text now (`TextComponent`, `BECore/Text/CLAUDE.md`), but there is no in-game UI to lay out a move list, a number or an opening name (No in-game UI (engine entry `in-game-ui`)).
4. Some choices a person needs still have no place to live. The side and the strength of the opponent have one now (the Side and Level buttons in the margins of the board, cycle buttons because the engine has no selector widget) and a new game is the Reset button. Still without one: resign, takeback, the piece of a promotion (a click on the last rank always plays the queen; the other pieces are reachable only through `TryMove` and UCI) and the board flip when the person plays Black (White stays at the bottom).

**Decided by the owner (2026-11-03), the opponent:**

1. An abstract engine interface in the game (`src/`) ("a move for this `Position` within this time or strength") that runs the search off the main thread through `TaskManager` and plays the answer with `TryMove` on the main thread, so the model and the scene stay as they are.
2. First implementation: Stockfish as a separate child process over UCI (the logic of `UciEngine` in `tools/stockfish_bridge.py` ported to C++), the path chosen by the user, nothing shipped. This keeps GPL-3.0 code out of the game and out of `engine/` (other games of the engine may be sold; GPL code must never enter `engine/`). It works on desktop only: the web target cannot start a process and Android only in ways an app should not rely on.
3. Later, behind the same interface: an engine of our own in `src/` (alpha-beta over the existing `MoveGenerator`), in the game's process on every target and deterministic for a fixed depth (the manual clock and the smoke tests need that). Linking Stockfish in is not planned.
4. Confirmed by the owner (2026-11-03, after the first slice): Stockfish is never shipped or linked, because the repository has no license file; the user downloads and installs it. No Stockfish binary, source, network file or copied text goes into the repository.
5. The path of Stockfish (2026-11-03, second slice): a line in the game's own config first, then the environment variable `STOCKFISH`, then `stockfish` on `PATH`. `config/ChessSettings.xml` is committed and carries no path (an empty `stockfishPath`); a person puts their own in `config/ChessSettings.local.xml`, which git ignores. A file picker comes later, when the in-game UI has one (engine entries `in-game-ui` and `ui-authoring`).
6. The interface (2026-11-03, second slice): the person picks the side they play and the strength of the opponent in the window, and the window shows that the computer is thinking and says what went wrong when the engine fails. The engine has no selector widget (a toggle, a dropdown), so the side and the strength are cycle buttons whose text is a variable.

**A fix has to cover** (the rest is a direction to confirm with the owner, not a decision):

- **the opponent:** as decided above;
- **the controls of a game:** side and strength are done (the Side and Level buttons; "Computer is thinking" and the engine's error are shown, so the game does not look frozen), and so is the new game (Reset). What is left: resign, takeback (rebuild from `startFen` + `moves`, or `UndoMove`), the promotion choice and the board flip, on the in-game UI and the text of the roadmap entries;
- **analysis** (needs the UCI engine of (a) for anything deeper than a basic evaluation of our own): an evaluation bar and a best-move hint after each move; a move list that can be clicked to view an earlier position without changing the game; a review after the game that evaluates every position in the background and marks the moves that lost the most; PGN export and import; opening names from a table. `MultiPV` and `go depth` give the lines;
- **the control API and tests:** done in this branch: the opponent is state of `ChessGameControl` (`get_state` has `opponent` with the side the program plays, the level, `thinking` and the error; `set_state` picks side and level, with `engine_unavailable` when there is no engine), so a model can play a game against the engine of the game itself, and a smoke scenario plays a move against the fake UCI engine on both clocks (`tests/control_smoke.py`). What remains: gtests of the engine on known positions with a real Stockfish (a mate in one and two, a hanging queen, a draw by repetition), a whole game against it, and `stockfish_bridge.py` as the independent referee of the rules and as the yardstick for the strength of our own engine (a match of a fixed number of games at a low `Skill Level`).
